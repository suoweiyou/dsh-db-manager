# 发布指南：dsh-db-manager → DSH 插件市场

> 调研结论（2026-09-09，基于本机 `dshmarket` v1.44.0 插件源码与 awesome-dsh-plugin 官方 contributing.md）：
> DSH 的可视化插件市场（dshmarket）检索的是 **awesome-dsh-plugin.com 的策展目录**（3400+ 插件），目录数据源是 GitHub 仓库
> `awesome-dsh-plugin/awesome-dsh-plugin` 的 `data/plugins/*.yml`（一个插件一个 YAML，PR 收录）。
> 因此"市场可搜到" = **npm 发布（可选但推荐） + GitHub 仓库 + 向目录提交 PR** 三步。

## 1. GitHub 仓库

1. 在 GitHub 创建**公开**仓库，建议名 `dsh-db-manager`（目录条目的 name 取自仓库名）。
2. 推送本项目（不要包含 `node_modules/`，`.gitignore` 已覆盖）。
3. 仓库 Settings → Topics 添加 `dsh-plugin`（还有 `deepseek-harness`、`mysql` 更好）。
4. 编辑 `package.json`：把 `"repository"` 字段填为你的仓库地址（发布 npm 前必须；格式 `"git+https://github.com/<owner>/dsh-db-manager.git"`）。
5. ✅ 已加 `screenshots.json`（仓库根，与 `package.json` 同级）。格式与约束（已对官方 `scripts/probe-screenshots.mjs` 逐条核对）：
   - 三种形状都接受：裸数组 `["docs/img/a.png", …]`（本项目用这种）、`{"screenshots": […]}`、单键映射 `{"<条目URL>": […]}`；
   - **1–8 张**（`MAX_SHOTS = 8`），每项必须是非空字符串；
   - **相对路径**按仓库 `HEAD` 解析（`raw.githubusercontent.com/<owner>/<repo>/HEAD/<path>`），不得以 `/` 开头、不得含 `..`；中文文件名会被逐段 `encodeURIComponent`，取图正常；
   - 绝对 URL 只允许 https 且主机为 GitHub 托管（`raw.githubusercontent.com` / `user-images.githubusercontent.com` / `camo.githubusercontent.com` / `github.com`），防止截图变成跟踪像素；
   - 收录后由官方 `probe-screenshots.mjs` 定期校验存活：404/410 的图会被**静默摘掉**（不阻断构建），所以改文件名要同步改 `screenshots.json`。

## 2. npm 发布（推荐）

```bash
npm login                      # 你的 npm 账号
npm publish                    # 包名 dsh-db-manager 已确认为可用（2026-09-09 查 registry 404）
```

- 发的是**预构建包**（`files` 只含 `lib/`、`bin/`、`README.md`、`THIRD-PARTY-NOTICES.md`、`docs/img/`（README 截图）与两个 `cordis.patch*.yml`，无构建脚本）——市场安装可跳过 pnpm `allowBuilds` 审批，体验最好。
- `repository` 字段必须指向第 1 步的仓库，否则市场无法关联 npm↔仓库。
- 以后发版：改 `version` → `npm run build` → **打 tag 并建 Release**（正文必须写明支持的 DSH 区间与实测版本，规则见[开发规范 §7.2](开发规范.md)）→ `npm publish`。

> 注意：当前 `package.json` 已移除 `private: true`。`repository` 字段留待你建仓后填写（本指南 §1）。

## 3. 提交收录（PR 到 awesome-dsh-plugin）

向 `github.com/awesome-dsh-plugin/awesome-dsh-plugin` 提 PR，**只新增一个文件** `data/plugins/<你的GitHub用户名>__dsh-db-manager.yml`：

```yaml
url: https://github.com/<owner>/dsh-db-manager
name: <owner>/dsh-db-manager
category: tools
description:
  en: 'MySQL connection registry for DSH: settings-page connection manager with status view, shadow backups before UPDATE/DELETE, and safe AI query tools.'
  zh: 'MySQL 连接管理插件：设置页可视化管理连接与状态，UPDATE/DELETE 前自动影子备份受影响行，内置只读白名单与高危确认的 AI 查询工具。'
```

规则要点（全文见该仓库 contributing.md）：

- 只填 `description.en` 也可，`zh` 可留空等维护者补；含 `: ` 的描述必须加引号。
- 描述**必须属实**（会对照代码核对），不带营销词。
- 一个 PR 最多 3 条；只改自己的条目。
- CI 自动检查：`dsh.bundle` 清单、仓库年龄（≥1 天）、awesome-lint 与站点构建。失败信息会明确指出改什么，推同一分支即可。
- 合并后 awesome-dsh-plugin.com 自动重建，dshmarket 市场（含 china 镜像路线，走 npm 镜像 `dsh-plugin-catalog` 包）即可搜索到本插件。

## 4. 用户安装方式（收录后）

- **市场 UI**：设置 → 插件市场 → 搜索 "db-manager" → 一键安装（自动应用 `cordis.patch.yml`，无需手动改补丁）。
- **CLI**：`dsh plugin --profile web add dsh-db-manager`（npm）或 `dsh plugin --profile web add github:<owner>/dsh-db-manager`（源码）。
- ⚠ 已手动挂载本插件的用户（如你本机的 Junction + 手工 patch 行）应**先移除手动补丁行**再改用市场安装，避免同一插件重复挂载。

## 1. 背景与定位

### 1.1 需求来源与痛点

用户在 DSH（DeepSeek Harness）中进行多项目日常开发，每个项目各自拥有独立的数据库（MySQL 5.7/8.x、PostgreSQL、SQLite）。当前痛点：

1. **工具割裂**：查看表结构、核对数据需要切换到 Navicat/DBeaver 等独立 GUI 工具，与 AI 编程会话割裂；DSH 内的 Agent 无法直接感知数据库真实状态（表结构、数据、迁移结果）。
2. **多项目多库管理繁琐**：连接配置缺少"工作区 → 关联数据库"的项目级组织方式；连接健康状态（可达性）没有统一的可视视图。
3. **AI 辅助开发缺一环**：AI 没有查询数据库的能力，只能生成 SQL 让用户手动执行再贴回结果。

### 1.2 产品定位与 GUI 范围决策

- **定位**：AI 原生的数据库访问层插件 + 轻量连接管理 GUI；内部开发者工具（非 toC/toB 商业产品）。消费者为开发者（GUI 操作者、配置作者）与 DSH 会话中的 AI Agent（模型工具调用方）。
- **管理面（浏览器 GUI）**：承担**连接管理**——查看已配置的数据库连接与状态（可达性/最近测试结果）、连接增删改、连通性测试、默认连接设置。
- **数据面（模型工具）**：库表浏览、数据查询、SQL 执行等高频探索性交互由**模型工具**承担（对话即界面）。理由：连接管理低频、结构化、适合表单；数据浏览/查询高频、探索性、与 AI 协作天然契合。未来若需数据面 GUI，服务层与 RPC 设计不阻碍该演进。
- **需求真实性**：用户明确要求"能连接和管理和查看 mysql 数据库，多个项目时会有多个数据库需要链接，一个工作区保存关联多个数据库"，并先后决策"不做 GUI"（v0.2）→"撤回，连接管理需要浏览器端 GUI"（v0.4）；真实多库环境（不同项目各自 MySQL 5.7 / 8.x 实例）佐证需求来自日常而非推测。

### 1.3 受益方与价值

| 受益方 | 场景 | 获得的价值 | 优先级理由 |
|--------|------|-----------|-----------|
| 开发者（主用户） | 在设置页集中查看/维护多项目数据库连接与状态 | 连接按全局/工作区组织一次配置长期复用；连接健康状态一目了然，无需打开第三方 GUI 验证 | P0：连接管理 GUI 是用户明确要求的可视面 |
| DSH 会话中的 AI Agent | "查一下 order 表最近 10 条"、"确认迁移后新字段存在" | 通过注册的模型工具直接执行只读查询，回答有据可依，减少幻觉 | P0：本插件区别于普通 GUI 的核心价值 |
| 开发者（数据变更场景） | 执行修复 SQL、验证写入结果 | 受控写执行通道（高危确认闭环 + 影子备份 + 影响行数回报 + 审计留痕），比裸命令行安全 | P1：有真实需求但频率低于查询 |

### 1.4 竞品调研结论

| 方案 | 类型 | 对本需求的差距 |
|------|------|----------------------|
| Navicat / DBeaver / TablePlus | 独立 GUI | 独立于 DSH；无 AI 工具集成；连接管理不与"项目/工作区"绑定；无连接健康视图与会话联动 |
| VS Code Database Client 等 IDE 插件 | IDE 内嵌 | 绑定 VS Code，无法被 DSH 会话中的模型调用 |
| 社区 MySQL MCP Server | 协议服务器 | 需单独安装运行进程；与 DSH 工具/审批/工作区体系无原生整合；无 GUI、无状态视图 |
| DSH 动态插件临时实现 | 会话内临时插件 | 纯 JS、无模块加载能力，无法携带 mysql2 等第三方依赖，生命周期仅限当前进程 |

**结论**：以"**AI 工具为数据面、轻量 GUI 为管理面**"形成差异化——① 与 DSH 工作区/会话/设置页体系原生集成（GUI 是设置页原生分区）；② 以工作区为单位组织多连接，配置文件声明式可版本化；③ 连接状态可视化与连通性测试内建。采用 **DSH 正式插件包（Host + Client 双端）**形态实现。

## 2. 迭代目标与成功衡量

### 2.1 目标（G1–G6）

1. **G1 连接配置管理**：JSON 配置文件 + GUI 两种途径声明与维护数据库连接（含工作区关联与全局共享），配置加载严格校验并解密，修改可重载，重启 DSH 后仍可用。
2. **G2 连接管理 GUI**：DSH 设置页出现"数据库"分区；查看全部连接（名称/主机/端口/默认库/模式/来源）与状态（未测/可达+延迟/不可达+分类原因）；增删改、一键测试、默认连接标记。
3. **G3 连接可用性验证（双通道）**：GUI 按钮与会话工具 `db_test_connection` 均可测试连通性，返回分类错误（网络/认证/库不存在/权限）。
4. **G4 库表元数据与数据查询（AI 工具）**：模型可通过工具列出 databases/tables、描述表结构、执行只读数据查询，结果受行数/字节上限约束。
5. **G5 受控 SQL 执行**：读写模式连接可经工具执行写 SQL；高危语句走"拒绝 + 确认令牌 + 用户确认后重试"闭环；全程审计留痕。
6. **G6 安全基线**：密码 AES-256-GCM 加密落盘且永不进入对话/日志/工具返回/GUI 明文回显；默认只读模式；只读模式下写语句 100% 拒绝。

### 2.2 成功衡量

| 目标 | 衡量标准 |
|------|---------|
| G1 | 从编辑配置到 GUI/工具可见新连接 ≤ 1 分钟（含重载）；重启 DSH 后配置完整保留 |
| G2 | 设置页"数据库"分区可见全部连接卡片与状态点；一次"全部测试"≤ 5 秒给出逐连接状态（局域网） |
| G3 | GUI 与工具的测试结果一致；对停用库/错密码/无权限分别返回对应分类错误 |
| G4 | 模型对"列出某库所有表 / 查某表前 N 行 / 描述某表结构"三类任务 100% 通过工具完成；局域网单次调用 ≤ 1 秒 |
| G5 | 高危语句 100% 触发确认闭环且重试必须携带有效确认令牌；审计日志完整 |
| G6 | 配置文件、日志、工具返回中 0 处明文密码；GUI 编辑表单不回显明文；只读模式写语句拦截率 100% |

## 3. 场景与用户流程

### 3.1 核心场景（谁-在什么情况-为什么需要）

- **场景 1（GUI 查看连接与状态）**：开发者打开 DSH 设置页 → 「数据库」分区 → 看到全部连接卡片与状态点（绿=可达+延迟，灰=未测，红=不可达+原因）→ 点「测试」立即刷新。需要：不打开第三方工具即可确认"哪个库现在连得上"。
- **场景 2（GUI 添加连接）**：接手新项目 → 点「添加连接」→ 填写名称/host/port/用户名/密码/默认库/读写模式 → 保存（host 端加密密码落盘）→ 新卡片自动测试转绿。需要：表单比手写 JSON 快，密码由 host 加密、不经对话。
- **场景 3（AI 查询）**：对话中问"users 表里最近注册的 5 个用户是谁" → 模型调用 `db_query` 执行只读 SQL → 返回列名+数据+耗时+截断标记。
- **场景 4（结构核对）**：迁移代码跑完后"确认 order 表有没有新字段 ship_date" → 模型调用 `db_describe_table` → 给出列清单与 DDL 片段。
- **场景 5（受控写执行）**：让 AI 生成修复 SQL 并执行 → `db_execute` 识别为无 WHERE 的 UPDATE → 拒绝并返回确认令牌与风险说明 → 模型向用户征询 → 确认后携令牌重试 → 返回影响行数并写审计。
- **场景 6（异常兜底）**：数据库已下线或密码已改 → GUI 状态点变红并显示分类原因；`db_test_connection` 返回同样信息与建议动作。

**场景-FR 覆盖映射**：场景 1/2→FR-1/2/3/16；场景 3→FR-7；场景 4→FR-6；场景 5→FR-8/9/10；场景 6→FR-5。全部 P0 功能点已被场景覆盖；**P1/P2 功能（FR-11/12/13）进入实现里程碑前，须先按「谁-在什么情况-为什么」补充对应场景，再行开发**。v0.13 新增 FR-18（设置页只读表浏览）作为 P1 已实现项，对应场景 4 的人操作镜像——开发者也能在设置页浏览表结构与 DDL，无需走模型工具。

### 3.2 用户流程

```text
配置阶段（GUI 或文件，二者操作同一份数据）
  设置页「数据库」分区：添加/编辑/删除/测试连接（host 端加密密码）
  或直接编辑 ~/.dsh/db-manager/connections.json（全局）
  与        <workspace>/.dsh/db-manager.json（工作区关联/私有/默认）
        ▼
  插件加载/重载 → zod 校验 → 密码延迟解析 → 连接档案就绪
        │
管理面（GUI，Client 半区）
  连接卡片列表 + 状态点 ──► 单连接测试 / 全部测试 ──► 状态即时刷新
        │
数据面（AI 工具，由用户在会话中驱动）
  db_list_connections ──► db_test_connection
  db_list_databases / db_list_tables / db_describe_table   （元数据）
  db_query        （只读白名单 + 自动 LIMIT + 结果截断）      （数据）
  db_execute      （读写模式 + 高危确认令牌闭环 + 审计）      （变更）
```

## 4. 功能需求（FR 总表）

优先级：P0 = 首版必须；P1 = 首版应有；P2 = 后续迭代。

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| FR-1 | 连接配置文件 | 全局 `~/.dsh/db-manager/connections.json` + 工作区 `<workspace>/.dsh/db-manager.json`；连接字段：name/dialect/host/port/username/password（`$ENV:VAR` 引用或 `enc:v1:...` 密文）/defaultDatabase/file(sqlite)/ssl/extraParams/mode(readonly\|readwrite)/comment/group（v0.21 展示用分组标签，1–64 字符，仅影响设置页分区，不参与连接解析）；zod 严格校验，非法配置拒绝加载并给出可读错误 | P0 |
| FR-2 | 工作区关联与连接选择 | 工作区文件声明私有连接、`useGlobal` 白名单（非空数组时仅列表内全局连接可见，空/缺省全部可见）、`default` 默认连接；解析顺序：工作区私有同名 > 全局兜底可见；工具未指定连接时取 default，无 default 且多连接时返回清单要求选择（当前会话工作区由工具执行上下文的会话 cwd 自动识别） | P0 |
| FR-3 | 密码加密与脱敏 | 密码支持 `$ENV:VAR` 引用与 AES-256-GCM 密文；工具返回/日志/错误信息统一脱敏（不出现密码、完整连接串）；`db_list_connections` 不返回任何凭据字段；GUI 编辑不回显明文 | P0 |
| FR-4 | 配置热重载 | 配置文件变更后支持会话内重载（`db_reload_config` 工具 + 下次调用 mtime 自动检测）；GUI 保存后立即生效 | P0 |
| FR-5 | 连接测试 | `db_test_connection`（工具）与 GUI 测试按钮同源：建连 + `SELECT 1`，返回耗时或分类错误（网络不可达/认证失败/未知库/权限不足/超时） | P0 |
| FR-6 | 元数据工具 | `db_list_databases` / `db_list_tables`（含视图，标注类型）/ `db_describe_table`（列、索引、DDL） | P0 |
| FR-7 | 只读查询工具 | `db_query`：仅 SELECT/SHOW/DESC/EXPLAIN 白名单（AST 校验 + 规范化复核）；未含 LIMIT 自动注入（默认 50，可参数化 ≤ 200）；自带 LIMIT 超过请求上限时外层收口；结果截断（默认 ≤ 200 行 / 1MB）并返回 `truncated` 与总数估计 | P0 |
| FR-8 | 读写模式 | 每连接 `mode` 字段；只读为默认；只读模式下写语句一律拒绝并说明原因（SQLite 在驱动层以 readOnly 强制） | P0 |
| FR-9 | 受控写执行 | `db_execute`：仅读写模式连接可用；UPDATE/DELETE 执行前自动影子备份受影响行到同库 `__dbm_backup_*` 表（备份策略三档可配，见 §7.2）；影响行数超 `backupMaxRows`（默认 10 万）或无法可靠定位（REPLACE/多表 JOIN/解析失败）时拒绝执行并附手工备份参考 SQL，用户确认后携 `backupAck` 跳过插件备份；备份行数与预计不一致即中止执行；高危规则（DROP/TRUNCATE/ALTER/RENAME、UPDATE/DELETE 无 WHERE、多语句写）命中时拒绝执行，返回 confirmToken（HMAC 绑定连接名+语句哈希+过期时间，一次性，默认 5 分钟）；宿主审批服务可用时优先走人工审批（拒绝即不签发令牌） | P0 |
| FR-10 | SQL 安全网关 | node-sql-parser AST 语句分类 + 自研规则层（多语句拆分、WHERE 缺失检测、LIMIT 注入、标识符转义白名单、EXPLAIN/INTO/USE/SET 拦截）；解析失败一律按最高危处理 | P0 |
| FR-16 | 连接管理 GUI | DSH 设置页「数据库」分区（settings.section）：①连接卡片列表（名称、host:port、默认库、方言徽章、readonly/readwrite 徽章、来源、默认连接标记）；②状态视图（未测/可达+延迟/不可达+分类原因+检测时间；手动"测试"与"全部测试"）；③操作：添加/编辑/删除（确认）、测试；④编辑表单密码策略：不回显、留空=保持不变、填入即由 Host 端加密；⑤GUI 不可用降级（Host 侧路由未启用时给出说明，工具不受影响） | P0 |
| FR-15 | 多方言支持 | `ConnectionSpec.dialect: 'mysql' \| 'postgresql' \| 'sqlite'`；schema 默认 `mysql`（向后兼容，不改旧配置）；工具、RPC、影子备份、确认闭环、错误分类、GUI 在三种方言上行为一致。详见 §7.1 | P0 |
| FR-18 | 设置页只读表浏览（v0.13） | 设置页「数据库」分区的连接卡片新增「查看表 / 收起表」按钮：展开面板列出某连接默认库的表/视图清单，按表查看列、索引与 DDL（按方言：MySQL `SHOW CREATE TABLE` / SQLite `sqlite_master.sql` / PG 系统目录 best-effort 重建）；**只读**，不提供数据行浏览入口（守住 §11"非目标"边界）；复用 `src/db/metadata.ts` 同源 driver 路径，三方言一致；SQLite 路径沙箱每次 acquire 重跑（与 GUI 测试按钮同约定） | P1（已实现） |
| FR-19 | 项目视图（v0.15） | 设置页「数据库」分区新增「项目」标签页：①项目列表 = 本插件**观察到的**会话工作区（`usage.json` + 当前活跃会话 cwd，不扫盘）；②每个项目展示其私有连接（`<项目>/.dsh/db-manager.json`，**可增/改/删/单测**）、该项目使用过的全局连接（usage 事实，只读）、`useGlobal`/`default` 与校验警告；③写操作按**工作区路径白名单** fail-closed（仅允许插件已观察到的项目）；④两个标签页均支持搜索过滤 | P1（已实现） |
| FR-20 | 复制连接（v0.21） | 连接卡片新增「复制」按钮：从**已存条目**复制一条连接（同一台服务器加库的典型场景），机密与 SSH 隧道原样搬运、页面全程不接触凭据；RPC `connections.duplicate`，写入层 `duplicateConnection()`；省略新名自动 `<源名>-副本`（重名递增），复制后**直接打开副本的编辑器**，改库名即可保存；可指定目标项目（`toWorkspace`，过白名单） | P1（已实现） |
| FR-21 | 连接分组与折叠（v0.21） | 连接新增展示用 `group` 标签（自由文本，1–64 字符，不参与连接解析）：同一标签的连接在设置页归入**可折叠分区**（分区头显示标签/数量/展开状态，折叠状态按来源分别记忆）；「全局连接」与每个项目的私有连接**都**支持；无任何分组时列表保持原样（不出现分区头）；编辑器「分组」字段带已有分组名 datalist，避免手误分裂分组 | P1（已实现） |
| FR-11 | 审计日志 | 全部工具调用与 GUI 配置变更写本地 JSONL（时间/通道/动作/连接名/语句（脱敏）/分类/状态/耗时/行数/是否确认执行；不含结果数据与凭据），按天滚动保留 30 天 | P1（已实现） |
| FR-12 | 结果导出 | `db_export`：查询结果写为 CSV/JSON 文件到工作区（流式，上限可配） | P2 |
| FR-13 | SSH 隧道连接（v0.16） | 数据库仅能从跳板机访问时：连接通过 `sshProfile` 引用**可复用**的 SSH 配置（`sshProfiles[]`，工作区覆盖全局），连库前先建 SSH 隧道并由本地回环端口转发（**只绑 127.0.0.1**）；认证方式支持 ssh-agent / 私钥文件（口令可留空 = 该私钥无口令）/ 内联 PEM / 密码；**主机密钥严格校验**（必须已存在 known_hosts，无 TOFU、无跳过开关；支持 `[host]:port`、哈希 `\|1\|salt\|hash`、`@revoked`）；SSH 机密与数据库密码同规则（仅 `$ENV:VAR` 或 `enc:v1` 密文，GUI 永不回显）；隧道随连接池条目级联关闭，SSH 配置参与缓存指纹；引用不存在的配置时**拒绝连接而非直连**（fail-closed）；主机密钥校验失败时给出**可直接粘贴执行的修复命令**（按认证方式拼 `-p` / `-i` / `-o UserKnownHostsFile`，写明目标 known_hosts 绝对路径，并提供 `ssh-keyscan` 兜底） | P2→P1（已实现） |

### 5.2 RPC 协议（GUI ↔ Host，同源 HTTP + 令牌鉴权）

`POST /db-manager/api/<method>`，头 `x-dbm-token`（进程内随机令牌，仅注入 DSH 自身页面；常量时间比较）：

- `connections.list` → `{ connections: [{ name, dialect, host, port, username, defaultDatabase, mode, scope, comment, group?, sshProfile? }], warnings }`（无密码字段；`group` 为 v0.21 的展示用分组标签）
- `connections.save` → 入参含连接字段（passwordMode: keep/env/plain/enc/none；plain 由 Host 端即时加密落盘）→ `{ ok, name }`；条目为**整体替换**，未传的可选字段（comment/group/sshProfile）会被清空
- `connections.move`（v0.20）→ `{ originalName, fromWorkspace?, toWorkspace?, connection }` → `{ ok, name, action: 'moved'|'updated', warning? }`；在全局与项目配置之间（或两个项目之间）搬迁一条连接：省略 `*Workspace` 即表示全局；两端项目路径均过 fail-closed 白名单；`passwordMode: 'keep'` 从**源**条目解析，机密原样搬运；先写目标后删源，源删除失败时返回 `warning`（连接已在目标位置，源可能残留）
- `connections.duplicate`（v0.21）→ `{ originalName, fromWorkspace?, toWorkspace?, name?, defaultDatabase?, group? }` → `{ ok, name, action: 'duplicated' }`；从**已存条目**复制一条连接（同一台服务器加库的快捷路径）：机密（`enc:v1:`/`$ENV:`）与 SSH 隧道逐字节原样搬运、**不解密**，可只覆盖 `name`/`defaultDatabase`/`group`（值为 `null` 或空串表示清除）；省略 `name` 时自动命名 `<源名>-副本`，重名则递增 `-副本2`、`-副本3`…（显式传入的 `name` 重名则拒绝）；复制结果先过 schema 校验再落盘，源条目非法则拒绝复制；两端项目路径同样过白名单，审计记录 `connections.duplicate`
- `connections.delete` → `{ ok }`（删除前 GUI 端确认）
- `connections.testAll` → `{ results: [{ name, ok, latencyMs?, errorKind?, message?, testedAt }] }`（并发 8；批量场景单次等待上限 2s，不采用连接的 `connectTimeoutMs`）
- `connections.test` → `{ result }`；可选 `workspace` 指定项目私有连接（经白名单校验）
- `connections.status` → 最近一次测试缓存（进程内存）
- `connections.usage` → 会话/工作区使用关联（按连接名聚合，进程内会话 + 持久化 `usage.json` 工作区）
- `workspaces.list`（v0.15）→ `{ workspaces: [{ path, configPath, exists, connections[], warnings[], useGlobal?, defaultConnection?, invalid?, globalUsage?: [{ name, count, lastUsedAt }] }] }`；项目列表 = `usage.json` 工作区 ∪ 活跃会话 cwd（不扫盘），连接字段与 `connections.list` 同形（无凭据）
- `workspaces.save`（v0.15）→ `{ workspace, originalName?, connection }` → `{ ok, name, action, workspace, path }`；写入 `<workspace>/.dsh/db-manager.json`，明文密码由 Host 即时加密；`workspace` 必须在白名单内，否则 422
- `workspaces.delete`（v0.15）→ `{ workspace, name }` → `{ ok }`；`workspace` 同样受白名单约束
- `sshProfiles.save`（v0.16）→ `{ originalName?, workspace?, profile: { name, host, port?, username, auth: { method, keyPath?, privateKey?/passphrase?/password?: { mode, plain?, env?, enc? } }, knownHostsPath? } }` → `{ ok, name, action, path }`；写入全局或（白名单内）项目配置；明文机密由 Host 即时加密；同名默认拒绝（`originalName` 才更新）
- `sshProfiles.delete`（v0.16）→ `{ name, workspace? }` → `{ ok, path }`
- `connections.list`（v0.16 扩展）→ 响应新增 `sshProfiles: [{ name, scope, host, port, username, authMethod, keyPath?, hasPrivateKey, hasPassphrase, hasPassword, knownHostsPath? }]`（**无任何机密值**）；连接项新增 `sshProfile?`
- `build.status`（v0.17）→ `{ available, libDir, loadedAt, loadedHash, currentHash, files, newestMtimeMs, stale }`；Host 启动时对自身 `lib/` 做内容指纹，页面据此判断「磁盘代码 ≠ 运行代码」并提示重启 DSH；**Host 过旧时（不认识本方法 → 404）页面同样按"需要重启"处理**
- `sshProfiles.test`（v0.17）→ `{ name, workspace? }` → `{ result: { name, ok, latencyMs?, errorKind?, message?, hint?, testedAt } }`；只做「建连 + 主机密钥校验 + 认证」，不做端口转发（验证凭据与 known_hosts，而非转发能力）；`workspace` 受白名单约束；成功与失败均 200（与 `connections.test` 一致）
- `tables.list { name, database?, workspace? }`（v0.13，v0.18 增 `workspace`）→ `{ ok, connection, dialect, database, tables: [{ name, type, comment?, rowsEstimate? }] }`，仅查询默认库（或显式 `database`）的表/视图清单；不返回任何数据行。`workspace` 指向项目私有连接（白名单校验，**项目定义优先于全局同名连接**）
- `tables.describe { name, table, database?, workspace? }`（v0.13，v0.18 增 `workspace`）→ `{ ok, connection, dialect, database, table, columns: [{ name, columnType, nullable, defaultValue?, key?, extra?, comment? }], indexes: [{ name, unique, columns[] }], ddl? }`，按方言（MySQL `SHOW CREATE TABLE` / SQLite `sqlite_master.sql` / PG 系统目录重建）输出 DDL；`workspace` 语义同上

### 5.3 工具协议（模型 → Host）

| 工具 | 说明 |
|------|------|
| `db_list_connections()` | 列出全局+当前会话工作区的连接（无凭据字段），标注 scope/默认/可用性 |
| `db_test_connection({ connection? })` | 建连 + `SELECT 1`；成功返回延迟，失败返回分类错误（network/auth/unknown-database/permission/timeout/config）与建议动作 |
| `db_reload_config()` | 重新加载配置文件，报告逐条校验警告，并对已消失连接关闭连接池 |
| `db_add_connection({ name, dialect?, scope?, host?, port?, username?, password?, defaultDatabase?, file?, mode?, comment?, replace?, test? })` | 一次调用完成连接注册（v0.14）：字段经 zod 严格校验 → 写入配置（`scope: global` 默认写全局文件，`workspace` 写当前会话工作区文件）→ 默认立即测试连通性并返回延迟或分类错误。明文 `password` 仅在入参出现，Host 端即时 AES-256-GCM 加密落盘（文件/返回值/审计均无明文）；同名默认拒绝，`replace: true` 时原地更新且省略 `password` 保留既有密文。取代「读配置 → 手写 JSON → 重载」的绕行流程 |
| `db_list_databases({ connection? })` | 列出该连接可见的数据库 |
| `db_list_tables({ connection?, database? })` | 列出某库的表与视图（名称/类型/注释/行数估计） |
| `db_describe_table({ connection?, database?, table })` | 表结构：列（类型/可空/默认/键/注释）、索引、DDL |
| `db_query({ connection?, database?, sql, limit? })` | 只读白名单通道：仅 SELECT/SHOW/DESC/EXPLAIN；无 LIMIT 自动注入（默认 50）；自带 LIMIT 超上限时派生表外层收口；结果截断（≤200 行/1MB）并标记 truncated；截断且为简单 SELECT 时附带 COUNT(*) 总数估计 |
| `db_execute({ connection?, database?, sql, confirmToken?, backupAck?, withBackup? })` | 受控写通道：仅读写模式连接；UPDATE/DELETE 执行前按备份策略自动影子备份；DROP/TRUNCATE/ALTER/RENAME、无 WHERE 的 UPDATE/DELETE、解析失败语句一律先拒绝并（宿主审批不可用时）签发 HMAC 确认令牌（绑定连接+语句哈希，5 分钟有效、一次性），用户同意后携令牌重试同一语句 |

> 两条通道均每次只接受一条语句（多语句直接拒绝，防止注入夹带）。

## 6. 技术方案

### 6.1 总体架构（Host + Client 双端）

插件采用 **DSH 正式插件包**形态（npm 包，ESM，Host + Client 双半区），通过 Cordis composition 挂载（一行插件 row 同时挂载双端：Host 半区为插件主体，Client 半区经 `dsh.client` 字段被浏览器装配）。不做 MCP 外挂进程，不依赖外部服务。

```text
┌──────────────── 浏览器（Client 半区，React 18） ────────────────┐
│  设置页「数据库」分区：连接卡片列表 / 状态点 / 增删改 / 测试      │
│  fetch('/db-manager/api/*', x-dbm-token)  ◄── RPC（JSON）       │
└───────────────▲─────────────────────────────────────────────────┘
                │ 令牌来自页面注入（webserver/index-inject global 行）
┌───────────────┴─────────────────────────────────────────────────┐
│                 DSH 主进程（Host 半区，Node.js ≥ 22）             │
│  dsh-db-manager Cordis 插件                                      │
│  ├─ ConfigStore       配置加载/校验(zod)/热重载 + 工作区解析       │
│  ├─ SecretResolver    密码解析：$ENV:VAR / AES-256-GCM 解密       │
│  ├─ PoolManager       三方言驱动缓存（规格指纹隔离、保活、失效重建）│
│  ├─ MetadataService   库/表/列/索引/DDL 元数据查询（按方言分派）    │
│  ├─ QueryService      分页查询、SQL 执行、超时与结果裁剪           │
│  ├─ SafetyGateway     语句分类、只读拦截、高危确认令牌             │
│  ├─ RpcRoutes         webServer 路由 + 令牌校验（GUI 数据通道）    │
│  ├─ AuditLog          JSONL 审计                                  │
│  └─ ToolsBridge       注册模型工具 db_*（JSON 参数/返回）          │
└──────┬──────────────┬──────────────┬───────────────────────────┘
       │ mysql2       │ pg           │ node:sqlite
  ┌────▼─────┐   ┌────▼─────┐   ┌────▼──────┐
  │ MySQL    │   │PostgreSQL│   │ SQLite 文件│
  │ 5.7/8.x  │   │          │   │ /:memory: │
  └──────────┘   └──────────┘   └───────────┘
```

### 6.2 双端职责划分

| 平台 | 承担内容 | 不承担内容 |
|------|---------|-----------|
| Host（Node.js） | 全部数据库 IO、配置与密钥、安全网关、模型工具、HTTP RPC 路由 | 不渲染 UI；不向浏览器返回密码明文 |
| Client（浏览器） | 设置页分区 UI（React），经带令牌的同源 fetch 调用 RPC | 不持久化任何数据；不持有密码明文（输入后即提交加密） |

### 6.3 技术选型

| 领域 | 选型 | 理由 |
|------|------|------|
| 插件形态 | Cordis 双端插件包（npm 包，ESM）+ composition row 挂载 | 官方插件既有形态；可携带自身 npm 依赖。动态插件无法加载 mysql2，不作为交付形态 |
| 语言/运行时 | TypeScript 5 + Node.js ≥ 22（v0.11 起），构建产物 `lib/*.js` + `.d.ts` | 与官方插件包一致；node:sqlite 要求 Node 22+ |
| MySQL 驱动 | `mysql2`（promise API） | 连接池、prepared statements、MySQL 5.x/8.x、`caching_sha2_password` |
| PostgreSQL 驱动 | `pg` | Node-API prebuilt；SQLSTATE 错误码映射 |
| SQLite 驱动 | Node 22+ 内置 `node:sqlite`（`DatabaseSync`） | 零 native binding、零 prebuilt、零编译工具链（v0.11 迁移，详见 §7.3） |
| 连接管理 | 驱动池（mysql2 createPool / pg Pool / sqlite 单连接）+ PoolManager（两级缓存：连接名 → 规格指纹键；并发 acquire 去重；close/retainOnly 精确归因） | 复用驱动池化能力，叠加 DSH 生命周期 |
| 配置存储 | JSON 文件：全局 `~/.dsh/db-manager/connections.json` + 工作区 `.dsh/db-manager.json`（`DSH_HOME` 环境变量优先） | 声明式、可版本化、便于备份迁移；GUI 与文件操作同一份数据 |
| 密码加密 | Node `crypto` AES-256-GCM，密钥为本机随机密钥文件（`~/.dsh/db-manager/secret.key`，首跑生成）；主推 `$ENV:VAR` 引用；配套 `bin/encrypt.js` CLI 供人工生成密文 | 密文落盘；环境变量形态零密钥管理负担；CLI 保证密文可离线生成、不经对话 |
| SQL 安全 | `node-sql-parser`（AST 分类）+ 自研规则层（多语句拆分、WHERE 缺失、LIMIT 注入、标识符转义、HMAC 确认令牌、EXPLAIN/INTO/USE/SET 拦截、规范化文本复核） | AST 判型可靠；解析失败按最高危处理 |
| 参数校验 | `zod`（配置与 RPC 入参）；插件 `Config` 用 `@deepseek-ai/schemastery`（宿主装载约定） | 官方包双栈惯例 |
| 模型工具 | `ctx.tools.register(defineTool({...}))`（`@deepseek-ai/dsh-tools`） | 官方工具注册协议 |
| GUI RPC | Host `webServer.register({ kind:'prefix', path:'/db-manager/api' })` + 进程内随机令牌经 `webserver/index-inject`（`{kind:'global'}` 行）注入页面；Client 同源 fetch 携带 `x-dbm-token` | 全部使用已验证的宿主能力；令牌保证仅 DSH 页面可调用；webServer 缺席时自动降级（工具不受影响） |
| Client UI | React 18；注册 `settings.section`（`{ id:'db-manager', label:'数据库' }`，页面组件收到 `{ close }`）；客户端包经 `window.__ModuleLoader__.load({ id, factory })` 装载（esbuild cjs + banner/footer 产出），externals 仅 react/react-dom | 与官方 client 包装载协议一致；不替换任何既有 UI 区域 |
| 审计 | 本地 JSONL（按天滚动，保留 30 天） | 零依赖、可 grep；不存敏感数据 |

### 6.4 数据模型

```ts
// 连接档案（配置文件声明；password 两种形态）
interface ConnectionSpec {
  name: string               // 引用名，如 "demo-dev"
  dialect?: 'mysql' | 'postgresql' | 'sqlite'   // 默认 mysql，向后兼容
  host?: string              // mysql/postgresql 必填
  port?: number              // mysql 默认 3306；postgresql 默认 5432
  username?: string          // mysql/postgresql 必填
  password?: string          // "$ENV:VAR_NAME" 引用 或 "enc:v1:iv:tag:cipher" 密文；sqlite 无
  file?: string              // sqlite 必填：数据库文件路径（受路径沙箱约束）
  defaultDatabase?: string
  ssl?: { enabled?: boolean; rejectUnauthorized?: boolean }
  extraParams?: Record<string, string>   // 透传驱动（时区、charset 等；危险键被 denylist 拒绝）
  mode?: 'readonly' | 'readwrite'        // 默认 readonly
  comment?: string
}

// 全局配置 ~/.dsh/db-manager/connections.json
interface GlobalConfig { connections: ConnectionSpec[] }

// 工作区配置 <workspace>/.dsh/db-manager.json
interface WorkspaceConfig {
  connections: ConnectionSpec[]   // 工作区私有连接
  useGlobal?: string[]            // 全局连接白名单（非空时仅列表内可见）
  default?: string                // 本工作区默认连接名
}

// RPC 令牌：进程内随机 32 字节，不落盘、不入配置；页面经 global 注入获得
```

工作区解析：可见集 = 工作区私有连接 ∪ 全局连接（`useGlobal` 非空时按白名单过滤；同名时工作区覆盖并输出显著警告）；`default` 取工作区 `default`，否则仅一条可见连接时取该条，否则未定（工具要求选择）。

### 6.5 关键流程

1. **配置加载**：插件 apply → 读全局（+可用时的工作区）配置 → zod 校验（逐条错误定位）→ 密码延迟解析 → 连接档案就绪；`db_reload_config`/mtime 变化重载；GUI 保存后自动失效缓存（池按规格指纹自愈）。
2. **连接测试（GUI 与工具同源）**：解析密码（$ENV/解密，失败→分类错误）→ 建独立连接（connectTimeout 5s）→ `SELECT 1` → 返回延迟或分类错误；GUI 结果缓存于进程内存（`connections.status`）。
3. **GUI RPC**：页面加载后 fetch 携带 `x-dbm-token` → Host 常量时间校验令牌 → 方法分发 → JSON 响应（无凭据字段）；非 DSH 页面/令牌不符 → 403。
4. **模型只读查询**：`db_query` → SafetyGateway AST 分类确认为只读（含 EXPLAIN/INTO 拦截 + 规范化文本复核）→ LIMIT 注入/收口 → prepared 执行 → 裁剪 → JSON 返回 → 写审计。
5. **高危写执行闭环**：`db_execute` → 分类 write/ddl → 读写校验 → 高危且无有效 token → 先请求宿主人工审批（可用时：allowed-once 执行 / rejected 拒绝且不签发令牌；不可用时退回令牌闭环：拒绝并返回 confirmToken 与风险说明）→ 模型向用户转述征询 → 携 token 重试 → 校验 → 影子备份（按策略）→ 执行 → 影响行数 → 审计"经用户确认执行"。非高危写直接执行并审计。
6. **插件停止/更新**：Cordis Fiber 回收全部注册（工具、路由、注入监听），PoolManager 关闭全部连接池，不留泄漏句柄。

## 7. 演进专题（重大设计决策）

### 7.1 多方言支持（v0.7 PostgreSQL / v0.8 SQLite / FR-15）

**连接配置**：每条连接显式声明 `dialect`，可选值 `mysql`（默认，向后兼容）/ `postgresql` / `sqlite`。已有配置文件零改动即升级可用。

**driver 抽象**：`db/dialect.ts` 暴露统一的 `DatabaseDriver` 接口（`query` / `execute` / `end` / `withTransaction`），工具、RPC、影子备份、安全网关只依赖这个接口；`db/mysql-driver.ts`、`db/pgsql-driver.ts`、`db/sqlite-driver.ts` 分别封装三个驱动。工具代码不出现 dialect 分支。

**跨方言一致性**：工具签名、返回结构、安全网关、确认闭环、错误分类、GUI 编辑器形态在三种方言上完全一致。差异只出现在：SQL 本身（元数据查询、影子备份 SQL）、错误码来源（MySQL `ER_*` / PG SQLSTATE / SQLite `SQLITE_*`）、driver 底层 API（mysql2 Promise / pg Pool / node:sqlite DatabaseSync）。

**占位符**：MySQL/SQLite 用 `?`；pg 用 `$1, $2, …`，由 pg driver 内部透明重写（跳过字符串字面量与注释），调用方继续用 `?`。

**元数据差异**：

| 元数据 | MySQL | PostgreSQL | SQLite |
|---|---|---|---|
| 列出数据库 | `SHOW DATABASES` | `pg_database`（过滤模板库） | `PRAGMA database_list` |
| 列出表 | `information_schema.TABLES` | `information_schema.tables`（过滤 schema） | `sqlite_master`（table/view，排除 `sqlite_%`） |
| 描述表 | `information_schema.COLUMNS/STATISTICS` + `SHOW CREATE TABLE` | `pg_attribute/pg_index/pg_class` + `format_type` 重建骨架 | `PRAGMA table_info / index_list / index_info` |
| DDL | `SHOW CREATE TABLE` 完整 DDL | 列级重建（约束/索引 best-effort） | `sqlite_master.sql` 真实保存的 CREATE 语句 |

**影子备份差异**：MySQL `CREATE TABLE x LIKE y`；PG `CREATE TABLE x (LIKE y INCLUDING ALL)`（PG ≥ 10）；SQLite 无 LIKE，用 `CREATE TABLE x AS SELECT * FROM y WHERE 0`（保留列结构，不复制 PK/约束——快速回退手段而非完整 schema 镜像）。

**错误分类**：三方言错误码统一映射到同一组 `DbErrorKind`（network/auth/unknown-database/permission/timeout/syntax/config/unknown），GUI 与工具看到的错误标签与建议动作完全一致。

**GUI 差异（最小）**：连接卡片方言徽章；编辑器按 dialect 切换 host/port/user/password 块 vs `file` 输入框（sqlite 自动 `passwordMode: 'none'`）；RPC `connections.list` 输出 `dialect` 字段。

### 7.2 备份策略与事务化（v0.10 / FR-9）

**问题驱动**：v0.5 引入的影子备份最初是无脑 always-on——每条 UPDATE/DELETE 都强制先建 `__dbm_backup_*` 表复制受影响行，对大表是灾难（备份 INSERT 全表扫描、锁持有时间叠加）。

**用户决策（2026-09-14）**：三档配置 + 默认 `small-only`。

```ts
backupDefault: 'always' | 'small-only' | 'opt-in'   // 默认 'small-only'
backupSmallThreshold: number                        // 默认 1000
```

**策略矩阵**（`db_execute` 另有 `withBackup?: boolean` tri-state 参数可强制覆盖）：

| `backupDefault` | 估算行数 ≤ 阈值 | 估算行数 > 阈值 | 估算行数未知 |
|---|---|---|---|
| `always`（旧行为） | ✅ 备份 | ✅ 备份 | ✅ 备份 |
| `small-only`（默认） | ✅ 备份 | ❌ 跳过 | ❌ 跳过（安全默认） |
| `opt-in` | ❌ 跳过 | ❌ 跳过 | ❌ 跳过 |
| 任意 + `withBackup: true` | ✅ 备份 | ✅ 备份 | ✅ 备份（强制） |
| 任意 + `withBackup: false` | ❌ 跳过 | ❌ 跳过 | ❌ 跳过（强制） |

**事务化备份路径**（v0.10 M6）：

```text
1. CREATE TABLE __dbm_backup（事务外 —— 绕开 MySQL InnoDB DDL 隐式 commit）
   ↓ 失败 → audit error
2. BEGIN
   2a. INSERT INTO backup SELECT …（二次校验：write 语句）
   2b. SELECT COUNT(*) FROM backup（二次校验：read 语句）
   2c. user SQL（二次校验：write 语句）
   ↓
   COMMIT（备份表保留在库中供事后审计/恢复）
   ↓ 失败 → ROLLBACK + DROP backupTable 清理 + audit error
```

关键保证：事务内任意一步失败 → ROLLBACK + 备份表 DROP → 数据库状态完全不变；备份行数与预计不一致即中止执行。策略跳过时不进入事务流程（零开销）。

**迁移注意**：老配置（无 `backupDefault`）自动用 `small-only`——**行为变更**：大表 UPDATE/DELETE 不再被自动备份；依赖 always-backup 的部署显式设 `backupDefault: 'always'`；临时强制备份传 `withBackup: true`。

### 7.3 SQLite 驱动迁移 node:sqlite（v0.11）

**根因**：`sqlite3@5.1.7` 只为 N-API 主版本 3/6 提供 prebuilt binary；Node 24 起 `process.versions.napi` 为 `undefined`，prebuild-install 找不到匹配 binary，回退 `node-gyp rebuild`（Windows 需要 Visual Studio Build Tools + Python），**npm install 失败且用户侧零调试空间**。

**用户决策**：迁移到 Node 22+ 内置 `node:sqlite` 模块（Node 官方路径）。

```ts
import { DatabaseSync } from 'node:sqlite'
const db = new DatabaseSync(file, { readOnly, allowExtension: false })
// prepare(sql).all/run(...params)；exec('BEGIN'/'COMMIT'/'ROLLBACK')；close() 同步
```

- 回调 API → 同步 API + Promise 包装；只读模式在 open 时以 `readOnly: true` 强制；`lastInsertRowid`（`number | bigint`）coerce 到 `number`；`?` 占位符原样透传。
- **收益**：npm 依赖 -5 项（sqlite3/bindings/node-addon-api/prebuild-install/tar）；Windows/Linux/macOS 安装 0 工具链；安装包 -10~20MB；真 sqlite 集成测试可在沙箱内跑。
- **部署要求**：DSH 主进程 **Node ≥ 22.3**（v0.11 要求 node:sqlite；v0.12.1 起需 22.3 以使用 `process.getBuiltinModule`，`package.json#engines` 已标注）。Node 18/20 部署需回退 v0.10 并自行解决 sqlite3 编译工具链（回退方案：`better-sqlite3` 或保留 sqlite3 + 文档警告）。

## 8. 安全设计与审计结论

### 8.1 安全基线（G6 落地面）

- **密码**：只存在于配置文件（`$ENV:VAR` 引用 / `enc:v1:` AES-256-GCM 密文）与 Host 进程内存（即用即取）；明文在 schema 层拒绝；密钥文件 `~/.dsh/db-manager/secret.key` 损坏时 fail-loud 不静默轮换；`bin/encrypt.js` 离线生成、明文不经对话。
- **出口脱敏**：工具返回、RPC 响应、错误文案、审计日志统一脱敏（`sanitizeSql` 覆盖 `$ENV/enc` 引用与 IDENTIFIED BY / SET PASSWORD / PASSWORD() / WITH PASSWORD 等全部 DCL 口令形态，三种引号风格）；错误文案不回显值片段。
- **SQL 安全网关**：单语句强制（`multipleStatements: false` 钉死）；只读白名单 kind 校验 + `SELECT … INTO OUTFILE` 拦截 + `EXPLAIN` 内层语句守卫（`EXPLAIN ANALYZE <写>` 直接 blocked）+ `USE/SET` 会话语句拦截；解析失败按最高危处理；规范化文本复核（sqlify 往返一致性，类别翻转即拒绝）。
- **确认闭环**：HMAC-SHA256 绑定连接名+语句 SHA256+过期（5 分钟）+ 一次性台账 + 常量时间比较；宿主审批服务可用时优先人工审批（拒绝不签发令牌），不可用退回令牌闭环并在风险说明中明示。
- **连接池**：两级缓存按连接名精确隔离（无 `::` 前缀归因），内层键含 spec 指纹（host/port/username/password/file/ssl/extraParams 的 sha256）——改配置即生效、旧驱动自动关闭。
- **SQLite 路径沙箱**：每次 acquire 重跑 `validateSqliteFilePath`（fail-closed）+ realpath 解析 + `root + path.sep` 防前缀攻击；工具路径 allowedRoots = 会话工作区。
- **extraParams 防线**：denylist 拒绝 `uri`/`connectionString`/`multipleStatements`/`ssl`/`localInfile` 等危险键（堵 mysql2 URI query 合并绕过），spread 后防御性剥离，身份/池策略/TLS 字段后置永不可覆盖。
- **GUI/RPC**：React 全 children 渲染（无 dangerouslySetInnerHTML）；令牌仅注入 DSH 页面 + 常量时间比较 + body 1MB 上限；配置原子写回；损坏配置文件拒绝保存/删除（防静默清空）。
- **审计**：目录 0700 / 日文件 0600（best-effort）；语句 ≤2000 字符 + 凭据打码；不含结果数据；30 天滚动清理。

### 8.3 已知边界（记录在案，非漏洞）

1. **审计含语句字面量**：数据面字面量（如 `UPDATE … SET token='…'`）会进审计文件（≤2000 字符），如需更强隐私可后续加 VALUES 检测。
2. **只读通道不承诺无副作用**：SELECT 调用带写副作用的存储函数/UDF 无法静态识别；COUNT 估算会二次执行该语句；根本缓解是 DB 侧最小权限账号。
3. **确认令牌非真人间隔**：宿主审批通道不可用时退回令牌闭环（工具描述强制要求 + 审计留痕缓解）。
4. **mysql2 客户端超时是"假超时"**：不终止服务器端执行；错误文案已如实提示并建议 KILL 核对。
5. **SQLite 测试路径 `process.cwd()` 兜底**：DSH 单进程模型的既有妥协（fail-closed）。
6. **Windows 密钥/审计文件 ACL**：`mode 0600` 在 Windows 依 profile ACL，与 DSH 进程同信任级。
7. **GUI 密码经回环 HTTP 提交**：仅本机回环 + 令牌门控，无 TLS（本机场景可接受）。

## 12. 风险与开放问题

| # | 问题 | 影响 | 当前倾向 |
|---|------|------|---------|
| 1 | 密钥管理策略：`$ENV:VAR` 为主、密文为辅，是否需要主密码模式 | 密码存储安全与易用平衡 | 首版双形态并存；密钥文件模式预留接口 |
| 2 | 高危确认强度：confirmToken 无法 100% 防止模型未经真实用户确认重试 | 数据安全 | 已升级：优先宿主人工审批（v0.9 H2）；审批不可用时退回令牌闭环 + 审计留痕 |
| 3 | GUI RPC 依赖 webServer 服务（Web profile 挂载） | 非 Web 形态 GUI 不可用 | 已设计降级：无 webServer 时不注册路由，GUI 半区自然不加载，工具不受影响 |
| 4 | 配置文件中密文形态的密钥文件管理（多机同步失效） | 体验 | 文档明示密文绑定单机；跨机用 $ENV 形态 |
| 5 | 模型工具结果上限与上下文占用的平衡 | Agent 体验 | 默认 50 行 + 截断标记 + 总数估计，可配置 |
| 6 | 生产库误操作风险 | 数据安全 | 默认只读 + 高危确认 + 影子备份 + 文档建议只读账号；不提供"跳过确认"配置项 |
| 7 | GUI 维护全局连接，工作区级连接仍以文件为主 | 体验一致性 | 按此边界交付（GUI 显示说明文案）；若需求强烈再评估 GUI 编辑工作区文件 |
| 8 | 低危跟踪项（详见 §8.3 与 records）：H3 effect cleanup 不等 pool close、M2 SQLite PRAGMA 误判、M3 PG `$$…$$` 不识别、M5 令牌台账内存态、L1 纯数字标识符、L2 备份表名碰撞、L3 Windows 密钥权限、L5 sqlite 大小写 | 资源/数据完整性 | 概率极低或无安全影响；用户反馈或下次审计时升级修复 |

## 附录 A：术语表

| 术语 | 含义 |
|------|------|
| DSH | DeepSeek Harness，本插件的目标宿主（Node 主进程 + 浏览器 Web GUI） |
| Cordis | DSH 的插件组合框架；插件以 composition 行挂载，生命周期内所有注册可逆 |
| Host 半区 | 插件运行在 DSH Node 进程中的部分：数据库 IO、服务、模型工具、RPC 路由 |
| Client 半区 | 插件运行在浏览器页面中的部分：设置页分区 UI，经带令牌的同源 fetch 调 Host |
| 工作区 | DSH 会话绑定的项目目录；本插件以工作区为粒度组织数据库关联 |
| SafetyGateway | SQL 安全网关：语句分类、只读拦截、高危识别、LIMIT 注入/收口 |
| confirmToken | 高危写执行的一次性确认令牌，HMAC 绑定连接名+语句哈希+过期时间 |
| settings.section | DSH 设置页的页面级 Slot（list 型）；本插件注册「数据库」分区 |
| 影子备份 | UPDATE/DELETE 执行前将受影响行复制到同库 `__dbm_backup_*` 表，供事后恢复 |

## 附录 B：配置与使用速查

### B.1 安装（挂载到 DSH）

1. 把本包（连同其自带 `node_modules`）复制或链接到 DSH 可解析位置，通常为 `<dsh 安装目录>/node_modules/dsh-db-manager`（推荐目录联接：`New-Item -ItemType Junction -Path <profile>/node_modules/dsh-db-manager -Target <本目录>`）。
2. 把 [cordis.patch.example.yml](../cordis.patch.example.yml) 中的 `insert` 块追加到部署 profile 的 `cordis.patch.yml`（或 `--patch` 覆盖层）。
3. 重启 DSH：设置页出现「数据库」分区；会话中即可使用 `db_*` 工具。市场安装（自动应用补丁）见 [发布指南](发布指南-插件市场.md)。

> 无 Web 服务器的运行形态自动降级：GUI 不加载，模型工具不受影响。`rpcEnabled: false` 可显式关闭 GUI 的 RPC 路由；`auditEnabled: false` 可关闭审计 JSONL。

### B.2 连接配置示例

**全局配置** `~/.dsh/db-manager/connections.json`（`DSH_HOME` 环境变量优先于 `~/.dsh`）：

```json
{
  "connections": [
    {
      "name": "3db1-dev",
      "dialect": "mysql",
      "host": "198.51.100.30",
      "port": 3306,
      "username": "dev_ro",
      "password": "$ENV:MYSQL_DEV_PW",
      "defaultDatabase": "acme_saas",
      "mode": "readonly",
      "comment": "管理系统开发库（只读账号）"
    },
    {
      "name": "3db2-pg",
      "dialect": "postgresql",
      "host": "198.51.100.31",
      "port": 5432,
      "username": "dev_ro",
      "password": "$ENV:PG_DEV_PW",
      "defaultDatabase": "acme_saas",
      "mode": "readonly"
    },
    {
      "name": "local-app",
      "dialect": "sqlite",
      "file": "./data/app.db",
      "mode": "readonly",
      "comment": "本地嵌入式应用数据库"
    }
  ]
}
```

**工作区配置** `<项目目录>/.dsh/db-manager.json`：

```json
{
  "connections": [
    { "name": "local-dev", "host": "127.0.0.1", "username": "root", "password": "enc:v1:…", "mode": "readwrite" }
  ],
  "useGlobal": ["demo-dev"],
  "default": "local-dev"
}
```

解析规则：可见连接 = 全局连接（`useGlobal` 白名单过滤）∪ 工作区私有连接（同名时工作区覆盖并警告）；默认连接取工作区 `default`，仅一条可见连接时自动选中。

### B.3 密码的两种形态

| 形态 | 写法 | 说明 |
|------|------|------|
| 环境变量 | `"$ENV:MYSQL_DEV_PW"` | 推荐；设置环境变量后重启 DSH 生效；跨机器通用 |
| 密文 | `"enc:v1:iv:tag:cipher"` | 本机密钥文件（`~/.dsh/db-manager/secret.key`，首跑自动生成）加密；**绑定单机** |

生成密文（在**你自己的终端**运行，明文不进入对话）：

```bash
node <插件目录>/bin/encrypt.js          # 交互输入（回显）；或 echo -n "secret" | node bin/encrypt.js
```

明文密码会被配置校验直接拒绝（含可读错误信息）。

### B.4 审计日志与使用关联

- 审计文件：`~/.dsh/db-manager/audit/YYYY-MM-DD.jsonl`（按天滚动，30 天自动清理；字段含时间/通道/动作/连接名/语句（单行化、≤2000 字符、凭据打码）/分类/状态/耗时/行数/是否确认执行；不含结果数据与凭据）。
- 会话/工作区使用关联：GUI 连接卡片显示「N 个会话在用 · M 个工作区关联 · 最近使用」；会话明细进程内（重启清空，≤32/连接），工作区聚合持久化 `~/.dsh/db-manager/usage.json`（≤64 工作区，跨重启可查"这个库被哪些项目用到"）。

### B.5 集成测试（可选）

单测默认全离线；对真实 MySQL 的端到端集成测试通过环境变量开启（套件自建/自毁临时库）：

```bash
DBM_TEST_URL=mysql://root:secret@127.0.0.1:3306 npm test
```

覆盖：连接发现与健康测试、元数据、只读查询（LIMIT 注入与截断+总数估计）、只读通道拒绝写、高危确认闭环、只读连接拒绝写、审计落盘且无凭据。

## 二、发现与处置

### L1【低·功能缺陷】browse 路径把 queryTimeoutMs 误用作 connectTimeoutMs —— 已修复

- **位置**: `src/rpc/routes.ts` `openForBrowse`
- **问题**: `pools.acquire(spec, { connectTimeoutMs: rt.queryTimeoutMs, ... })`——`BrowseRuntime` 只携带了 `queryTimeoutMs`，连接建立超时被错误放大到查询超时档位（默认 5000ms → 15000ms）。浏览一个不可达连接时 GUI 将等待 15s 才收到错误。
- **影响**: 可用性瑕疵，非安全漏洞。
- **修复**: `BrowseRuntime` 增加 `connectTimeoutMs` 字段；两个 RPC case 传入 `deps.connectTimeoutMs`；测试 `RT` 常量同步。

### L2【低·UX bug】「← 返回表列表」丢失已加载的表清单 —— 已修复

- **位置**: `src/client/Section.ts` `browseBack` / `browseSelectTable`
- **问题**: describe 阶段的状态未携带 `tables`，`browseBack` 重建 list 状态时 `tables` 为 `undefined`，面板显示「（该库没有表或视图）」——与实际不符（库内有表，只是状态丢了）。
- **影响**: 功能正确性 bug，非安全漏洞。
- **修复**: `BrowseState` 的 describe 分支增加 `tables?: TableListItem[]`；`browseSelectTable` 进入 describe 时从上一个 list 状态继承；`browseBack` 恢复时带回，无需二次 RPC。

### H1【加固·深度防御】tables.* 错误出口统一过 sanitize —— 已实施

- **位置**: `src/rpc/routes.ts` 两个 tables.* case 的错误响应
- **问题**: 外层 `handleRpc` catch 对未知异常统一 `sanitize()`（`$ENV:VAR` → `$ENV:***`、`enc:v1:…` → `enc:v1:***`），但 tables.* 分支内部的 `outcome.failure.message` 此前直传。当前所有错误消息来源（secrets 静态文案 / `toDbFailure` 的数据库错误映射）经核不含凭据值片段，实际风险为零；但按开发规范 §4.1「任何出口不得出现值片段」的深度防御要求，出口应统一打码。
- **修复**: 两个 case 的 `error` 字段统一 `sanitize(outcome.failure?.message ?? '未知错误')`。

## 三、已知边界（记录在案，非漏洞）

1. **database 覆盖参数可跨库浏览**：`tables.list { database }` 允许指定连接默认库以外的库名（MySQL/PG）。权限边界是该连接的数据库凭据（与 AI 工具 `db_list_tables({ database })` 行为完全一致），本机 DSH 页面持 token 者本就拥有同等能力，不构成提权。
2. **DDL/表清单无截断上限**：`SHOW CREATE TABLE` 等返回体可能较大，RPC 响应未截断。元数据非敏感；请求体有 1MB 上限、响应走本机回环 + token 鉴权。与 `db_describe_table` 工具行为一致。
3. **错误消息回显用户输入**：`连接 "${name}" 不存在` / `表 ${table} 不存在` 回显请求参数，未做长度截断（body ≤ 1MB 场景下可放大响应体）。与既有 `connections.test` 行为一致；JSON 响应 + React 文本渲染已消除注入面。
4. **连接删除后 browse 面板残留**：GUI 删除连接后已展开的表清单面板不会自动收起，后续点击会得到 422「连接不存在」提示（不崩溃、不泄露新数据）。UX 瑕疵，暂不处置。

## 复查确认通过项（新增/复核）

- **XSS**：`browsePanel` / `DescribeView` / `renderColumnRow` / `renderIndexRow` 全部 React 纯 children；DDL `<pre>` 背景修复后颜色均来自主题变量，无注入面。
- **SQL 注入**：`database` 参数化、`table` 经 `quoteIdentifier` 白名单——与首轮结论一致，本轮未改动。

- **池生命周期**：仍不调用 `driver.end()`（N2 契约）；`BrowseRuntime.connectTimeoutMs` 已由首轮 L1 修复带入。

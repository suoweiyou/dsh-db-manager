**审计范围**: 全部源码（Host 半区 12 文件、Client 半区 3 文件、CLI、配置/测试）
**审计方式**: 逐文件人工审查（注入面、鉴权面、密钥处理、确认闭环、渲染安全），发现问题即修复并补回归测试

## 一、发现并已修复的问题

| # | 严重度 | 问题 | 位置 | 修复 |
|---|--------|------|------|------|
| 1 | **高** | `SELECT … INTO OUTFILE/DUMPFILE/@var` 在 AST 里 kind 仍是 `read`，可经只读白名单通道在**数据库服务器上写文件/改会话变量** | `safety/classify.ts` | 新增 INTO 检测（`node.into` 含实际内容时）→ 标记 `blocked`，`db_query` 拒绝；注意 node-sql-parser 对普通 SELECT 也带 `into: { position: null }` 惰性标记，已区分（只有除 position 外还有内容才算真 INTO） |
| 2 | **高** | `USE db` / `SET …` 会永久改变共享连接池中某条连接的会话状态（后续复用该连接的查询落到错误的库/字符集） | `safety/classify.ts` | `use`/`set` 语句类型 → `blocked`（两个通道均直接拒绝，不走确认闭环；charset 引导写进 `extraParams`） |
| 3 | **中** | LIMIT 注入可被行尾注释吞掉：规则层兜底的语句保留原始文本，`SELECT 1 -- c` + 追加 `LIMIT 50` → LIMIT 落入注释，**查询变为无上限** | `tools/data.ts` | 提取 `injectReadLimit()`：AST 产物（无注释）直接追加；规则层产物**包裹派生表** `SELECT * FROM (…) AS __dbm_l LIMIT n`，注释无法吞掉外层 LIMIT |
| 4 | **中** | 确认令牌在 5 分钟内**可重复使用**（PRD FR-9 要求拒绝复用），同一条高危语句可被静默二次执行 | `safety/confirm.ts` | 增加已用令牌台账（Set，>512 时清理过期项）：成功校验即消费，重放返回「确认令牌已被使用（一次性令牌）」 |
| 5 | **中** | 密钥文件损坏（长度≠32）时**静默重建新密钥**，全部既有密文突然不可解密且无提示 | `secrets.ts` | 改为抛出 `SecretError`（含指引），文件保持原样不覆盖 |
| 6 | **中** | `SHOW CREATE TABLE \`db\`.\`table\`` 的标识符仅做反引号翻倍，未限制字符集（控制字符/引号可进入协议层） | `tools/resolve.ts` | `quoteIdentifier` 先按 `/^[\p{L}\p{N}_$]+$/u` 校验（支持中文表名），非法即抛可读错误 |
| 7 | 低 | GUI RPC fetch 无超时（Host 卡死时页面无限等待） | `client/api.ts` | 加 `AbortSignal.timeout(30_000)` |

## 二、审查后确认已安全的设计点（无需改动）

| 面 | 结论 |
|----|------|
| SQL 注入（元数据） | `information_schema` 查询全部参数化（`TABLE_SCHEMA = ?`），无拼接 |
| SQL 注入（数据通道） | `db_query` 白名单 + 单语句强制 + `multipleStatements` 默认关闭；高危写走「拒绝→HMAC 令牌→人工确认→重试同一语句」 |
| 多语句夹带 | 扫描器按引号/注释感知切分；`db_query`/`db_execute` 均一次一条，多语句直接拒绝 |
| WHERE 伪造 | 字符串/注释内容剥离后分类（`SET a='WHERE fake'` 仍判缺 WHERE 高危）；正则层不可被字符串内 `;` 欺骗 |
| 确认令牌伪造/篡改 | HMAC-SHA256 绑定（连接名+语句 SHA256+过期时间，进程内随机密钥）+ timingSafeEqual + 过期 5 分钟 + 单次使用 |
| RPC 鉴权 | 32 字节进程内随机令牌仅注入 DSH 页面；每请求校验；未设 CORS 头（跨域读被浏览器阻断）；请求体 1MB 上限；403/405 兜底 |
| 密码暴露面 | 配置仅存 `$ENV:`/`enc:v1`；明文在 schema 层拒绝；工具返回/RPC/审计统一脱敏；GUI 不回显 |
| 配置写入 | zod strictObject（含原型污染键拒绝）+ 临时文件原子重命名 |
| 客户端渲染 | 全部 React children（自动转义），无 `dangerouslySetInnerHTML` |
| 审计 | 语句 2000 字符截断 + 凭据打码（含 VALUES 内的 enc:$ENV 形态）；不含结果数据 |

## 三、已知边界（记录在案，非漏洞）

1. **确认令牌非真人间隔**：模型理论上可未经真实用户确认自行携令牌重试（缓解：工具描述强制要求 + 审计 `confirmed` 标记；升级路径：接入宿主审批栈，见 PRD 风险 #2）。
2. **Windows 密钥文件 ACL**：`mode 0600` 在 Windows 不生效，密钥文件对本机其他进程/用户可读——与 DSH 进程同信任级，README 已注明。
3. **GUI 密码经回环 HTTP 提交**：仅限本机回环 + 令牌门控，无 TLS（本机场景可接受）。
4. **令牌台账内存上限**：>512 条时先清理过期项；极端洪水下可能提前遗忘个别未过期令牌（影响：需要重新发起一次拒绝流程，无安全后果）。
5. **GCM IV 随机 12B**：低频配置写入场景碰撞概率可忽略。
